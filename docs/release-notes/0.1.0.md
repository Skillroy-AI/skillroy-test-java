## 1. What 0.1.0 is

Skillroy Test (Java) is a framework for testing Java desktop applications (Swing, optionally with embedded web views)
from inside the JVM. A small **Java 8 agent** is loaded into the application under test (as a `-javaagent`, by dynamic
attach, or embedded through the application's own plugin mechanism) and offers *primitives* over a loopback JSON-RPC
channel: read the Swing tree, click and type without taking focus, answer dialogs, query the application's database
connection, observe application events. A **Java 25 controller** compiles YAML scenarios into committed plans, runs them
with an event-based step protocol (no sleeps), and reports JUnit XML.

Scenarios state what they need ("a staff member whose return limit is below this item's deposit"). The values that fit
are found once, at the start of a run (by committed queries, or with a language model's help), checked in the target
with the application's own code, and frozen into a bindings file. CI replays the bindings with **zero model calls**,
and a cost ledger asserts it. In interactive use a person or an authoring tool drives a live target with a model in the
loop; every step goes through the same step protocol and is journaled, so that interactive work exports as an ordinary
scenario. Nothing in the build needs a model key.

What phases 1-7 built (the roadmap is §8 of [`base-framework-design.md`](../design/base-framework-design.md); each phase
has a contract in [`../design/`](../design/)):

| 6 | Hooks on shaded Byte Buddy and Byteman in process (both optional pieces of the agent home), a JDK 25 target through `JAVAAGENT`, the Windows path (built where Linux can test it, not verified on Windows), OpenTelemetry export from the controller (off by default), the tenant-pack overlay, and the repeat security review |

Not built: the fluent Java API (README), a trace viewer and a second transport (`TODO.md`, "Not yet assigned to a phase").
Phase 6's exit criterion that names a Windows host is not met, because no such host exists.

**Requirements.** The build and the controller need JDK 25 or newer (the build refuses an older one; the CLI launcher
checks for Java 25 and exits with code 69 otherwise). Target applications run on Java 8 through 25. Maven 3.9.

**Build.** `mvn -q verify` runs every test that needs no display. Display tests, the Java 8 target legs and the `jcef`
profile run in the Linux image through `ci/run-in-linux.sh` (README, "Build"). Never `mvn install`; build one module with
`mvn -o verify -pl <module> -am`.

**What it produces.** The CLI distribution comes from `controller/skillroy-cli`: `target/skillroy-cli/` (`bin/skillroy`,
`bin/skillroy.bat`, `lib/*.jar`) and `target/skillroy-cli.zip`, with `LICENSE`, `NOTICE` and a `THIRD-PARTY.txt`. The
agent home comes from `agent/skillroy-agent-dist`: `target/skillroy-agent/` and `target/skillroy-agent.zip`, eleven jars
with versionless names; `skillroy attach <pid> --home <agent home>` loads it, or the target starts with it as
`-javaagent`. No file read for this draft names a channel for publishing the zips or jars; that goes with the owner's word
on the release (B1).

*The five of B26 Q22 (pass 1, accepted by the owner on 2026-10-10, B28):*

1. **S36 part (b).** `StatementGuard` is a safety net, not the boundary. A statement can pass its check and still have
   effects the check cannot see: give the data account a read-only role, and set `readOnlyMode: always` on PostgreSQL
   sources (a deny-list of side-effect function names is not built).
2. **S37 option (i).** Run outputs take the process umask. `run.jsonl`, captures, bindings, ledgers and span files hold UI
   snapshots, events and row samples. On a shared host run the controller under `umask 077` and give `--out` a directory
   you own that others cannot write to, never a path directly under `/tmp` (a run refuses an output directory another
   user owns or others may write to without the sticky bit, and never writes through a file or link already in place,
   S97 and S99 of pass 2). That a private umask is the advice and not the default is what is accepted.
3. **S40, the pinning part.** Pin the image and the actions in your copy of `ci/examples/nightly-re-resolve.yml`: the
   base image of `ci/Dockerfile` by digest and every action by its commit SHA. The example itself names floating tags,
   because a pinned example rots within weeks.
4. **S48.** The Playwright driver inherits the controller's environment: `DEBUG=pw:*`, `NODE_OPTIONS`,
   `PLAYWRIGHT_NODEJS_PATH` and `PLAYWRIGHT_DRIVER_DIR` change what it runs or logs, so set them only on purpose
   (documentation only; a minimal driver environment is not built).
5. **S60, the `CLAUDE_CONFIG_DIR` part.** The planner's `claude` session transcript stays in the CLI's own data
   directory. On a shared host run `author` with a key and your own `CLAUDE_CONFIG_DIR`.

*Three of pass 2 (accepted by the owner on 2026-10-10, B28):*

6. **S77 (residual; the finding itself, P2-L4-F1, is fixed).** When the CDP path attaches while the agent reports no CDP
   target id, a process that holds the configured remote-debugging port before the application's browser engine binds
   it can answer the attach's WebSocket handshake with an HTTP redirect, which Playwright's driver follows: to another
   host, or to a Unix socket the operator can open. It gains an outbound connection with Playwright's headers and
   Playwright's own DevTools commands, never the run's scripts or typed values. Bind the port in the application first,
   or run such scenarios with `web.path: agent`. (The closing designs, a deferred attach or a controller-side WebSocket
   relay, are not built.)
7. **S84 (P2-L5-F4).** `ANTHROPIC_BASE_URL` may name plain `http` on `127.0.0.1`, `::1` or `localhost`. If the proxy there
   is not listening, another user of the host who binds its port receives the key in clear with the next request. Use a
   loopback `http` base URL only for a proxy you run, never on a shared host; prefer `https` on loopback. (Read with the
   fixed S96: a telemetry header may not travel over `http`, the model key may; the owner accepted that as it stands.)
8. **S94 (P2-L7-F4).** On a Windows whose built-in account names are not English, the owner-only checks cannot recognise
   the system account and the administrators group by name, so a directory or file created under a directory that passes
   those entries on by inheritance (the user's `%TEMP%`, the profile) is refused. Nothing is exposed; the framework
   refuses to run there. Remedy: create a directory, remove its inheritance and grant only yourself (`icacls <dir>
   /inheritance:r /grant:r "%USERNAME%":(OI)(CI)F`), and point `java.io.tmpdir`, `discoveryDir` and the credentials file
   at it. Not verified on a Windows host.

*Two of the Phase 7 delta review (accepted by the owner on 2026-10-11, B31):*

9. **S142 (L7-F4).** On Windows a directory junction (`mklink /J`, which needs no privilege) in place of a run's
   `failure/`, `captures/` or `candidates/` directory, of the per-scenario output directory, or of a bindings
   environment's `<id>.images/` directory is taken for an ordinary directory and judged by its target's owner. The run
   then writes its PNG files into, and deletes files of its own names from, the directory the junction points at, if the
   operator owns it. A symbolic link in the same place is refused unless the operator owns it. Give `--out` and the
   working copy a directory under your profile whose ACL others cannot write. Not verified on a Windows host. (A code
   remedy, comparing the real path, is named in the finding for a later Windows host.)
10. **S144 (L7-S2).** On Windows, run output, a session's `captures/` (a screenshot of every screen the model acted on),
    `candidates/`, `failure/image-*.png` and an uncommitted `<id>.images/` directory inherit the access list of the
    directory they are created in. The `umask 077` remedy of the POSIX hosts has no counterpart there, and a folder under
    `C:\` gives every local user read access by default. On a shared Windows host give `--out` and the working copy a
    directory under your profile, or remove inheritance from the directory you choose. Not verified on a Windows host.

**Other limits that `SECURITY.md` states** (design limits and conditions of use, not accepted findings; read them before
running the agent on a shared host): attach is the platform's trust boundary (B13); `ATTACH` on Java 21 and newer prints
the JEP 451 warning; hooks on Java 25 print one class-data-sharing warning line (B26 Q14); settings files must be your
own; redaction hides a rectangle, not a value, and a page's pixels are masked as a whole or not at all; with vision on,
pixels leave for the model provider (and, under the default `fallbacks: true`, a fallback model of the same provider
sees redacted captures too); the Robot tier presses where the pointer lands, and the Robot opt-in must not be committed;
committed image baselines and a session's `captures/` are screenshots.

## 3. Behaviour changes a user can see

From the "what it changed" and "behaviour changes" paragraphs of `DECISIONS.md` B27 (Phase 6 build and fixes, confirmed
2026-10-10), B30 (Phase 7 build and fixes, confirmed 2026-10-11) and the follow-ups B32 (confirmed 2026-10-11), B33 (the
owner's answers) and B34 (provisional: waiting for `B34 ok`). Nothing was released before, so these are changes against
earlier builds of the project. One line each; decision ids in brackets.

**Agent and control channel**

- A request with a body must carry the signed header `X-Skillroy-Body-Sha256`; a controller built before this cannot call
  a newer agent (D262, B27; nothing was released on protocol 0.2).
- A `hook.<id>` declared after the target is ready holds its state when `hook.install` answers (D449, B30; the one Phase 7
  decision that changes Phase 6 behaviour).
- A capability declared after the target is ready reads `UNAVAILABLE("not probed yet: declared after the target was
  ready, its probe is queued")` until its probe has run (D490, B32).
- `hook.events` refuses an `id` that is not a hook id (`INVALID_PARAMS`, `param: id`) and answers `hook.*` topics only
  (D491, B32).

**Model, sessions, MCP and credentials**

- A configured model id that is not in the price table is refused when the gateway opens, naming the `prices:` key; a
  configuration that worked before now fails (S52, B27).
- A pack's tool descriptions pass the key-mask rule, so prose that looks like `key: value` reads redacted in the session's
  tools and the MCP tool list; the sample's `signOn` and `authorise` are the example (D210, B27).
- No credential-joined slot is ever a model's or a client's argument, in any spelling; their steps resolve against the
  slots' public values; nothing that changes the target runs for them while a credential is in flight; a slot the person
  bound is not rebound by them; their bindings are exported as `REQUIRED` (D463, D464, D467, D468, B30).
- A text that names a credential slot as a whole is refused by the recorder before the session, so no refused step is
  journaled; the vocabulary sentence names the rule, and the five Phase 5 session recordings were regenerated (D487, D488,
  B32).
- `skillroy_scenario_run` in `approve` is refused without an approver and never writes into the bindings root; an
  images-only `approve` writes nothing at bind time; `approve` with `REJECT_ALL` after an environment change ends
  `RESOLUTION_FAILED / NOT_APPROVED` (D482, B30).
- The turn's first message lists the slots the person bound (D444, B30).
- `skillroy session --play` binds a scenario's fixture slots as the person, a credential slot included (D425), and
  evaluates the plan's `verify` after the last step, so a played scenario can now end `FAIL` where it ended `PASS`
  (D443, B30).
- `skillroy session` without `--out` writes into a new owner-only temporary directory and prints its path (D485, B30).
- The planner's prompt is its standard input, and a `.cmd` or `.bat` planner is refused (npm's `claude.cmd` is passed over
  for a native `claude.exe`) (D250, D252, B27).
- Amended in the first security pass and confirmed with B26 (Q18-Q21): `web.waitFlag` runs a caller's expression, so it is
  marked `script` and refused in read-only mode; one session meter per MCP server bounds `skillroy_session_ask`,
  `skillroy_resolve` and a run's tier (b) slots; an MCP client never confirms (a verb's own `confirm` is not honoured for
  it) and the verb gate runs at call time; a capture's bytes reach an MCP client only with the inference settings'
  `images: true`, otherwise a text resource names the written file.

**Files, settings and telemetry**

- A run refuses an output directory another user owns or others may write to (without the sticky bit), and never writes
  through a link or into a file already in place (D282, D283, B27). On Windows the directory's access list is judged too
  (S141, Phase 7; not verified on a Windows host).
- `telemetry.yaml` and `inference.yaml` are read only when they are the current user's and no other user may write them
  (D280, B27).
- A telemetry header is sent to an `https://` endpoint only, the default `http://127.0.0.1:4318` included (D281, B27; read
  with S84 above).
- Every read of a scenario's bindings file by the binder, the session and the executor follows the link rule of the
  writers: a link at the file's position, dangling or not, makes the file unreadable, and a writing bind refuses it
  instead of replacing it (D489, B32; D486, B30).

**Masking, capture and web**

- A mask on a container hides the text, value and mark of everything inside it, and a capture the heap cannot hold is
  refused, never silently scaled down (D383, D384, B30). A masked label's name and the text under a mask's `regions` are
  withheld too (D452, D454).
- A browser a pack's `CaptureMask` names is masked on every route: no pixels, text or tree for a model or a client (D471,
  B30).
- The image comparison blanks a focus owner's rectangle only up to a quarter of the compared raster, so a baseline approved
  while the compared component held the focus may need re-approval if the focus differs at replay (D481, B30).
- A `web.browsers` entry may carry an optional `blockedBy`, and the agent sends the browser's whole `bounds` (D404, D475,
  B30). The sample's committed `keypad-image` baselines carry three masks (D403).

**Pointer input and the Robot tier**

- The controller's Robot and glass gates read `via` and `mode` as the agent does (any case, white space trimmed), and a
  `$slot` reference that resolves to Robot is refused at the call (D440, D441, B30).
- A Robot press refuses a point in a minimised frame or a window it owns, a point no screen shows, and `modifiers`; a
  press received by another component makes the next action probe delivery again (D450, D451, D459, B30).
- A model or an MCP client can no longer paste, copy or cut through the person's clipboard or the X11 selection, or press
  the middle button, through any tool or raw primitive; an application's own Paste control stays an ordinary click, so mask
  it (D470, B30).
- *Provisional (B34):* the Robot may press past a window that owns the target's window while the target's window is the
  active one, for the point and a drag's end point; the hit test still reports the owner under `covering` (D492).

**JxBrowser adapter (provisional, B34)**

- Pointer input is no longer marked "input unverified" on JxBrowser 8: one descriptor role per event type, the wheel's
  deltas negated; modifier keys stay refused (D493).
- Registering an observer waits at most 2 s for the Chromium process (not at all on the event dispatch thread), and a late
  registration is unsubscribed at once (D494).

**SPI additions** (for pack and module authors): the session facade and the tool-set interface gained a few methods (D420,
D421), `ExecutorSession.fixture` (D425) and `ExecutorSession.namesSecret` (D487).

**Unchanged by the owner's choice (B33, 2026-10-11).** Replay refuses an unapproved value for a model's strategy only
(gap 93), and `web.dom.click` and `web.dom.fill` do not refuse a page under a modal dialog for a model or a client (gap
96; the recorder's path stays closed, D472). D495-D499 (B34) concern the sample web host and its checks only.
